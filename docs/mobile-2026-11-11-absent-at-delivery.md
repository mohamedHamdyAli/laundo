# تغيير API — العميل مش موجود وقت التسليم (التطبيقين)

**التاريخ:** ١١ نوفمبر ٢٠٢٦
**لـ:** فريق تطبيق العميل + فريق تطبيق المندوب
**الحالة:** ✅ **نازلة على laundo.nahrdev.net** (١١ نوفمبر ٢٠٢٦، `9cb8532`) — جاهزة تتبعت.

---

## الخلاصة

لو المندوب راح يسلّم الطلب والعميل مش موجود («العميل غير متاح» = `customer_unavailable`)،
الطلب **بيرجع للعميل يختار ميعاد تسليم جديد** — زي ما بيحصل في الاستلام من ٨ نوفمبر.
قبل كده الرحلة كانت بترجع للمناديب (فالإشعار كان بيروح لهم مش للعميل)، وبعد محاولتين
كانت بتبان «فشلت».

**مفيش حقل جديد ولا endpoint جديد** — نفس شاشة «اختيار موعد جديد» اللي شغالة مع «طلب التأجيل».

## تطبيق العميل

| فين | قبل | دلوقتي |
| --- | --- | --- |
| إشعار `reschedule_needed` | بعد التأجيل، وغياب العميل وقت الاستلام | **وكمان غياب العميل وقت التسليم**. النص: «المندوب ماقدرش يلاقيك عشان يسلّمك الطلب … اختار ميعاد تسليم جديد». `data.order_id` زي ما هو. |
| `GET /orders/{id}/reschedule` | | `needs_new_time: true` و**`leg: "delivery"`**. المواعيد اللي قبل ما الخدمة تخلص عليها `too_early: true`. |
| `POST /orders/{id}/reschedule` | `msg` كانت دايمًا «هنستلم الطلب فيه» | `slot_id` + `date` بس. **الخدمة مابتتغيرش** — أي حقل تاني بيتجاهل. لو `leg: "delivery"` الـ`msg` بقت «تم تحديد موعدك الجديد. هنوصّلك الطلب فيه.» |
| `GET /orders/{id}` | | `needs_new_time: true` لحد ما العميل يختار — **أو لحد ما خدمة العملاء تسند الرحلة لمندوب** بعد ما يتفقوا مع العميل في التليفون. |
| إشعار التأجيل (`customer_postponed`) على التسليم | «… عشان نستلمه» | «الطلب … تم تأجيله. اختر موعداً جديداً عشان نوصّلهولك.» |

### المطلوب

١. إشعار `reschedule_needed` يفتح شاشة إعادة الجدولة — واقروا `leg` منها: `delivery` = «ميعاد التسليم»، `pickup` = «ميعاد الاستلام».
٢. الشاشة دي **الميعاد بس** — متعرضوش اختيار خدمة ولا قطع.
٣. **اقروا `needs_new_time` قبل ما تفتحوا الشاشة.** لو بقت `false` (خدمة العملاء سندت الرحلة
   خلاص) اعرضوا الطلب عادي — `POST` في الحالة دي بيرجّع «الطلب ده مش مستني ميعاد جديد».

## تطبيق المندوب

| فين | قبل | دلوقتي |
| --- | --- | --- |
| `POST /driver/tasks/{id}/fail` بـ`customer_unavailable` على «التسليم للعميل» | الرحلة بترجع للمناديب (`requeued: true`) | الرحلة بتقف (`status: failed`, **`requeued: false`**) ومحدش بيتبعتله لحد ما العميل يختار ميعاد. |

### المطلوب

١. **بعد أي `fail` ارجعوا لقايمة المهام.** الرحلة مابقتش بتاعة المندوب، فـ`GET /driver/tasks/{id}`
   بيرجّع **404** «المهمة غير موجودة» — وده اللي ظاهر دلوقتي لو التطبيق بيعيد تحميل تفاصيل الرحلة
   بعد التعذّر. ده مش جديد (كان بيحصل مع أي تعذّر)، بس بقى بيتشاف أكتر.
٢. لو حابين رسالة للمندوب: `requeued: false` مع `customer_unavailable` = «العميل هيختار ميعاد جديد».
