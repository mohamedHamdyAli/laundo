# ٢٢ سبتمبر ٢٠٢٦ — الدفع والأسعار

ملفين في واحد. الجزء الأول **شغّال دلوقتي** ومحتاج منكم شغل. الجزء التاني
**جاي مع الريليز الجاي** ومش محتاج كود، بس محتاج تعرفوه.

---

# ١. الدفع — الأوردر مش بيتدفع لما `pay` ينجح

ده أهم سطر في الملف: **`POST /orders/{id}/pay` بيفتح محاولة دفع، مش بيدفع.**

اللي بيحصل إن الرد بيرجع `201` ومعاه `redirect_url`، فطبيعي حد يفتكر إن
العملية خلصت. هي ماخلصتش. الأوردر بيفضل `payment_status = "unpaid"` لحد ما
البوابة تبعتلنا إنها حصّلت الفلوس.

## طرق الدفع الأربعة مش بتتصرف زي بعض

| `method` | بيحصل إيه | الأوردر يبقى `paid` إمتى |
|---|---|---|
| `cash` | مفيش معاملة أصلاً. بنسجّل بس إن العميل اختار كاش. | عند الباب، لما السواق يحصّل |
| `wallet` | خصم فوري من المحفظة | **في نفس الريكوست** |
| `card` | بيرجّع `redirect_url` لصفحة الدفع | لما الـwebhook يوصل |
| `instapay` | نفس `card` | لما الـwebhook يوصل |

`cash` بيرجّع `200` مش `201`، و`payment_id` بتاعه `null`، و`status` بيبقى
`"cash_on_delivery"`. متعاملوهوش على إنه فشل.

## الفلو الصح لـ card و instapay

```
1)  POST /api/v1/orders/{id}/pay        { "method": "card" }
    -> 201 { payment_id, status: "pending", transaction_reference,
             amount, redirect_url }

2)  افتحوا redirect_url للعميل (WebView أو براوزر)

3)  لما يرجع، اسألوا:
    GET /api/v1/orders/{id}/payments
    -> لستة المحاولات بحالاتها

4)  الأوردر بقى مدفوع لما تلاقوا محاولة حالتها "captured"
```

**متفترضوش النجاح من رد الخطوة ١.** الخطوة ٣ هي اللي بتقول.

## ليه بيخليكم تدفعوا كذا مرة؟

لأن لسه **مفيش بوابة دفع حقيقية متركّبة**. اللي شغال دلوقتي `FakeGateway`،
وهو بيقلّد صفحة دفع مستضافة: بيدي `reference` و`redirect_url` وبيستنى الـwebhook
اللي عمره ما بييجي، لأن مفيش بروڤايدر يبعته.

يعني الأوردر عمره ما بيوصل `paid`، وبالتالي الحارس اللي بيرفض الدفع المكرر
مابيشتغلش — مش لأنه مكسور، لأنه شرطه ماتحققش.

**ومفيش دفع مكرر بيحصل.** كل محاولة جديدة بتلغي اللي قبلها، فمفيش لحظة فيها
محاولتين حيّين مع بعض. لو ضربتوا `pay` تلات مرات هتلاقوا:

```
1 pending  ·  2 failed (failure_reason: superseded_by_a_new_attempt)
payment_status = unpaid  ·  المحصّل = 0.00
```

## إزاي تجرّبوا الفلو كامل دلوقتي

بعد الخطوة ١، خدوا الـ`transaction_reference` وابعتوا ده بإيديكم — ده بديل
البوابة الحقيقية لحد ما تتركّب:

```
POST /api/v1/payments/webhook/fake
{
  "reference": "FAKE-XXXXXXXXXX",
  "event": "captured"
}
```

الأوردر هيبقى `paid` على طول. وبعدها لو ضربتوا `pay` تاني:

```
400  { "msg": "This order has already been paid." }
```

**ده للتجربة بس.** لما تتركّب بوابة حقيقية هي اللي هتبعت الـwebhook، والـendpoint
ده مش هيبقى مستخدم من التطبيق خالص.

## حاجات تانية بترجع ٤٠٠ وعايزة رسالة على الشاشة

| الحالة | الرسالة |
|---|---|
| الأوردر مدفوع خلاص | `This order has already been paid.` |
| المغسلة لسه ماعدّتش القطع | `The final price is not ready yet.` |
| مفيش مبلغ مستحق | `There is nothing to pay on this order.` |

الرسالة جاية في `msg`. اعرضوها زي ما هي بدل رسالة عامة — التلاتة دول بيوصفوا
مواقف مختلفة تمامًا والعميل محتاج يعرف أنهي واحدة.

# ٢. الأسعار هتزيد في الريليز الجاي (مفيش شغل كود)

في **رسم منصة** جديد بيتحمّله العميل، و**مدموج في سعر القطعة** — يعني مفيش
حقل جديد ولا endpoint جديد ولا سطر جديد في الفاتورة. الأرقام بس هي اللي
هتتغير.

الـendpoints اللي أسعارها هتزيد:

- `GET /api/v1/catalog`
- `POST /api/v1/orders/quote`
- وبالتبعية إجمالي أي أوردر جديد

**شكل الرد ما اتغيرش.** `price` لسه string بخانتين عشريتين زي ما هو.

## اللي محتاج منكم

**لو بتعملوا cache للأسعار، فضّوه بعد الريليز.** غير كده مفيش حاجة.

## حاجة تطمّنوا عليها

الفاتورة بتفضل تجمع صح:

```
سعر القطعة × الكمية = إجمالي السطر
مجموع السطور        = المجموع الفرعي
المجموع + الضريبة    = الإجمالي
```

الرسم مدموج في سعر القطعة نفسه عشان بالظبط السبب ده — لو كان اتضاف كسطر
مخفي، العميل كان هيطرح اللي شايفه من اللي دفعه ويلاقي فرق مالوش اسم.

**وقت الريليز مش هيزيد أي سعر من نفسه.** النسبة بتتظبط على صفر، ومحدش هيشوف
فرق لحد ما صاحب المنصة يحدد النسبة بإيده من لوحة التحكم.

## ولو العميل وافق على سعر والنسبة اتغيرت بعدها؟

مابيتأثرش. النسبة بتتختم على الأوردر وقت ما يتعمل، وعمرها ما بتتقرا تاني —
نفس قاعدة الضريبة بالظبط. فأوردر اتعمل النهاردة بيفضل بسعره حتى لو النسبة
اتغيرت بكرة وهو لسه في المغسلة.

---

## ملخص اللي عليكم

1. **متعتبروش `pay` نجح يعني اتدفع.** اسألوا `GET /orders/{id}/payments` واستنوا `captured`.
2. **`cash` رده مختلف** — `200`، `payment_id: null`، `status: "cash_on_delivery"`.
3. **اعرضوا `msg` زي ما هي** في حالات الـ٤٠٠ التلاتة.
4. **للتجربة دلوقتي**: ابعتوا الـwebhook بإيديكم عشان تشوفوا الفلو كامل.
5. **فضّوا cache الأسعار** بعد الريليز الجاي.
